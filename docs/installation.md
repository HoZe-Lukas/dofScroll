## 1. Install from a GitHub release

### Where the files are

Releases are published on the repository's Releases page:
<https://github.com/HoZe-Lukas/dofScroll/releases>. The newest stable release is under
<https://github.com/HoZe-Lukas/dofScroll/releases/latest>. Versions `0.x` and tags with a suffix
are marked as pre-release and are not shown under `/latest`; open the Releases page for them.

A release is created by the GitHub Actions workflow when a tag `v<version>` is pushed
(see [releasing.md](releasing.md)).

### Assets

The names come from the CPack configuration (`packaging/cpack/DofscrollCPack.cmake`) for
version `0.1.0`. Replace the version with the one you download.

| Asset | Meaning |
|---|---|
| `dofscroll-0.1.0-Linux.tar.gz` | TGZ archive, checked. Any Linux, install by hand. |
| `dofscroll-0.1.0-1.x86_64.rpm` | RPM for the RHEL family (built on Rocky Linux 9). Name pattern from CPack `RPM-DEFAULT`, unverified. |
| `dofscroll_0.1.0_amd64.deb` | DEB for the Debian family (built on Debian 12). Name pattern from CPack `DEB-DEFAULT`, unverified. |
| `SHA256SUMS.txt` | SHA-256 checksums of all other assets. |

### Verify the download

Put all files in one directory and run:

    sha256sum -c --ignore-missing SHA256SUMS.txt

Every file you downloaded must print `OK`. If one prints `FAILED`, delete it and download it again.
The checksums protect against a damaged download. They come from the same release page, so they
do not protect against a compromised release.

### RPM (RHEL, Rocky, Alma, Fedora family)

`spacenavd` and `libspnav` are not in the base repositories of RHEL 9 and its clones. Enable
EPEL first:

    sudo dnf install -y epel-release
    sudo dnf install ./dofscroll-0.1.0-1.x86_64.rpm

The package declares the dependency `spacenavd` (CPack setting `CPACK_RPM_PACKAGE_REQUIRES`).
The shared libraries (`libspnav`, X11, GTK, appindicator) are added by rpmbuild's automatic
dependency detection (unverified). `dnf` installs what is missing.

### DEB (Debian, Ubuntu family)

    sudo apt install ./dofscroll_0.1.0_amd64.deb

The package declares the dependency `spacenavd` (`CPACK_DEBIAN_PACKAGE_DEPENDS`). Library
dependencies are generated by `dpkg-shlibdeps` (`CPACK_DEBIAN_PACKAGE_SHLIBDEPS`). The DEB was
built against `libayatana-appindicator3`. Whether `spacenavd` exists in your release's
repositories: unverified.

### TGZ

The archive has the top directory `dofscroll-0.1.0-Linux/` and contains a tree rooted at `usr/`.
Extract it and copy it into `/usr` (or another prefix):

    tar xzf dofscroll-0.1.0-Linux.tar.gz
    sudo cp -a dofscroll-0.1.0-Linux/usr/. /usr/

You must install the dependencies yourself (see [section 4](#4-build-from-source) for the
package names; the run-time packages are the non-`-devel` ones).

### What a package installs

Checked on the TGZ built on a RHEL 9 machine:

| Path | Content |
|---|---|
| `/usr/bin/dofscroll`, `/usr/bin/dofscroll-tray` | The programs. |
| `/usr/lib64/systemd/user/dofscroll.service`, `dofscroll-tray.service` | User units. The directory is `<libdir>/systemd/user`, where `<libdir>` is the build machine's CMake library directory (`lib64` on RHEL). On Debian it is probably `lib/x86_64-linux-gnu` (unverified). |
| `/usr/lib64/udev/rules.d/70-dofscroll-uinput.rules` | uinput rule (same `<libdir>` caveat). |
| `/usr/share/dofscroll/examples/` | Example configs, `default/` and `modes/`. |
| `/usr/share/dofscroll-tray/icons/dofscroll-tray.svg` | Tray icon. |
| `/usr/share/locale/de/LC_MESSAGES/dofscroll.mo` | German translation. |
| `/usr/share/doc/dofscroll/` | `LICENSE` and a copy of the readme. |

Known problems of the current packages (to be fixed in the build; check the release notes):

- systemd looks for user units in `/usr/lib/systemd/user`, not in `/usr/lib64/systemd/user`.
  On RHEL the installed units are therefore not found. Step 3 of the setup below works around it.
- Both unit files contain `ExecStart=/usr/local/bin/...`, but the packages install into
  `/usr/bin`. The setup below patches the paths.
- udev reads `/usr/lib/udev/rules.d`, not `/usr/lib64/udev/rules.d`. Install the rule by hand
  (step 5).

## 2. First-time setup

Do these steps once per machine. Steps 1 and 5 need root.

1. Enable the SpaceMouse driver:

        sudo systemctl enable --now spacenavd

2. Check that the driver sees the device:

        systemctl status spacenavd

3. Make the user units available to your user. Find them first (`rpm -ql dofscroll | grep service`,
   or `dpkg -L dofscroll | grep service` on Debian), then copy them and fix the program path:

        mkdir -p ~/.config/systemd/user
        cp /usr/lib64/systemd/user/dofscroll*.service ~/.config/systemd/user/
        sed -i 's#/usr/local/bin/#/usr/bin/#' ~/.config/systemd/user/dofscroll*.service
        systemctl --user daemon-reload

   Use the directory that `rpm -ql` printed. If your package already installed working units
   (a build with the fixed paths), skip this step.

4. Start the services. They then start with every graphical session:

        systemctl --user enable --now dofscroll.service dofscroll-tray.service

5. Optional, only for Wayland or if you set `BACKEND = uinput`: install the udev rule for
   `/dev/uinput`:

        sudo cp <path of 70-dofscroll-uinput.rules> /etc/udev/rules.d/

   Get the path from `rpm -ql dofscroll | grep rules` (`dpkg -L dofscroll` on Debian). Then:

        sudo udevadm control --reload && sudo udevadm trigger

   Log out and in once. Details and the reason why you must not join the `input` group:
   [packaging/README-uinput.md](../packaging/README-uinput.md). If `/dev/uinput` does not exist,
   run `sudo modprobe uinput`.

### First start: seeding

When the tray starts and no config exists, it creates `~/.config/dofscroll/dofscroll.conf` from
`examples/default/dofscroll.conf` and copies the example modes into
`~/.config/dofscroll/modes/`. It never overwrites an existing file. The daemon cannot write to
that directory, so only the tray seeds. Without the tray, copy the files yourself:

    mkdir -p -m 0700 ~/.config/dofscroll/modes
    cp /usr/share/dofscroll/examples/default/dofscroll.conf ~/.config/dofscroll/
    cp /usr/share/dofscroll/examples/modes/*.conf ~/.config/dofscroll/modes/

The tray looks for the examples in `$DOFSCROLL_EXAMPLES`, next to the executable, in
`../share/dofscroll/examples`, then `/usr/local/share/dofscroll/examples` and
`/usr/share/dofscroll/examples`.

### Check that it works

    systemctl --user status dofscroll.service
    journalctl --user -u dofscroll.service -f

The log shows the device name and button count when the SpaceMouse is connected. Hardware
behavior (scrolling, zoom, buttons) can only be confirmed by you on your device. See
[troubleshooting.md](troubleshooting.md) if it does not work.

## 3. Upgrade, uninstall, migration

### Upgrade

Install the newer package over the old one:

    sudo dnf upgrade ./dofscroll-<new>.rpm       # or: sudo dnf install ./dofscroll-<new>.rpm
    sudo apt install ./dofscroll_<new>_amd64.deb # Debian family
    systemctl --user daemon-reload
    systemctl --user restart dofscroll.service dofscroll-tray.service

Your config in `~/.config/dofscroll/` is never touched by a package. If you copied the units
in step 3, repeat the copy and the `sed` command when the unit files changed in the release
notes.

### Uninstall

    systemctl --user disable --now dofscroll.service dofscroll-tray.service
    rm -f ~/.config/systemd/user/dofscroll.service ~/.config/systemd/user/dofscroll-tray.service
    sudo dnf remove dofscroll        # or: sudo apt remove dofscroll
    sudo rm -f /etc/udev/rules.d/70-dofscroll-uinput.rules   # if you installed it

Your config stays. Remove it with `rm -r ~/.config/dofscroll` if you want. For a TGZ install,
delete the files listed in "What a package installs".

### Migration from the old `spnav-scroll` names

The project used to be called `spnav-scroll`. Old config paths
`~/.config/spnav-scroll/spnav-scroll.conf` and `~/.config/spnav-scroll.conf` are still read as a
fallback. The tray copies the old file to `~/.config/dofscroll/dofscroll.conf` when it starts (a
symlink is recreated as a symlink). The old file is not deleted. After you checked the settings:

    rm -r ~/.config/spnav-scroll ~/.config/spnav-scroll.conf

Old units and binaries are not removed automatically. Remove them:

    systemctl --user disable --now spnav-scroll.service spnav-scroll-tray.service
    rm -f ~/.config/systemd/user/spnav-scroll*.service
    sudo rm -f /usr/local/bin/spnav-scroll /usr/local/bin/spnav-scroll-tray

Restart the tray unit once after the first start of a new version
(`systemctl --user daemon-reload && systemctl --user restart dofscroll-tray.service`) so the
current sandbox settings apply.

## 4. Build from source

### Dependencies

Run the check first. It lists missing packages and prints the install command for your distribution:

    cmake -S . -B build
    cmake --build build --target check-deps

| Distribution | Packages |
|---|---|
| RHEL 9 family | `sudo dnf install -y epel-release` then `sudo dnf install -y gcc-c++ cmake pkgconf-pkg-config spacenavd libspnav-devel libX11-devel libXtst-devel gtk3-devel libappindicator-gtk3-devel gettext` |
| Debian family | `sudo apt install g++ cmake pkg-config libspnav-dev libx11-dev libxtst-dev libgtk-3-dev libayatana-appindicator3-dev gettext` (taken from the CI job and the check-deps target; the Debian line is unverified here) |

CMake 3.16 or newer is required. If your system has an older one: `pip install --user cmake`.
`gettext` is only needed for the German translation.

### Configure, build, test, install

    cmake -S . -B build
    cmake --build build -j4
    ctest --test-dir build --output-on-failure
    sudo cmake --install build                    # default prefix /usr/local
    sudo cmake --install build --prefix /usr      # or choose a prefix
    DESTDIR=/tmp/stage cmake --install build      # stage for inspection

Options at configure time:

| Option | Default | Effect |
|---|---|---|
| `-DDOFSCROLL_TRAY=OFF` | ON | Build only the daemon, no GTK needed. The tray unit and icon are then not installed. If GTK or appindicator is missing, CMake warns and skips the tray. |
| `-DDOFSCROLL_HARDEN=OFF` | ON | Switch off the hardening flags. |
| `-DDOFSCROLL_SANITIZE=ON` | OFF | ASan/UBSan build. |
| `-DDOFSCROLL_WERROR=ON` | OFF | Treat warnings as errors. |

The install rules put the units in `<prefix>/<libdir>/systemd/user` with the same caveats as in
[section 1](#what-a-package-installs). With the default prefix `/usr/local` the unit paths
`/usr/local/bin/...` are correct, but systemd does not read `/usr/local/lib*/systemd/user`
by default, so still copy or link the units as in step 3 of the setup (skip the `sed`).

Packages: `cd build && cpack -G TGZ` (also `RPM` with `rpmbuild`, `DEB` with `dpkg-deb`).

### Run from the build tree

For development, link the build results instead of installing copies. The target only prints
the commands and runs nothing with sudo:

    cmake --build build --target install-user-links

Run the printed commands. The binaries then come from `build/`, the units from `systemd/` in the
checkout, so a rebuild takes effect after a restart. Stop the services before rebuilding
(`Text file busy`): `systemctl --user stop dofscroll.service dofscroll-tray.service`. Do not move
the checkout afterwards, or the links break.

Other targets: `check-fast` (-Werror build and tests), `check` (adds sanitizers, cppcheck,
hardening check), `check-config` (validates the example configs), `lint`, `install-udev`,
`uninstall` (uses `install_manifest.txt`).

## 5. Windows and macOS

The Windows and macOS ports are in development and there is no installer yet. Nothing in this
guide applies to them. The plan and the state of each work package are in
[work-plan.md](work-plan.md).
