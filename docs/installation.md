## 1. Install from a GitHub release

### Where the files are

Releases are published on the repository's Releases page:
<https://github.com/HoZe-Lukas/dofScroll/releases>. The newest stable release is under
<https://github.com/HoZe-Lukas/dofScroll/releases/latest>. Versions `0.x` and tags with a suffix
are marked as pre-release and are not shown under `/latest`; open the Releases page for them.

A release is created by the GitHub Actions workflow when a tag `v<version>` is pushed
(see [releasing.md](releasing.md)).

### Assets

The names come from the CPack configuration (`packaging/cpack/DofscrollCPack.cmake`) for
version `1.0.0`. Replace the version with the one you download.

| Asset | Meaning |
|---|---|
| `dofscroll-1.0.0-Linux.tar.gz` | TGZ archive, checked. Any Linux, install by hand. |
| `dofscroll-1.0.0-1.x86_64.rpm` | RPM for the RHEL family (built on Rocky Linux 9). Name pattern from CPack `RPM-DEFAULT`, unverified. |
| `dofscroll_1.0.0_amd64.deb` | DEB for the Debian family (built on Debian 12). Name pattern from CPack `DEB-DEFAULT`, unverified. |
| `dofscroll-1.0.0-windows-x64-setup.exe` | Windows per-user installer (unsigned), see section 5. |
| `dofscroll-1.0.0-windows-x64-portable.zip` | Windows portable folder, no installer. |
| `dofscroll-1.0.0-macos-arm64.dmg` | macOS disk image for Apple silicon (ad-hoc signed, not notarized), see section 5. |
| `SHA256SUMS.txt` | SHA-256 checksums of all other assets. |

If Qt was not available when a Windows or macOS package was built, its name contains
`-daemon-only` and it has no settings window.

### Verify the download

Put all files in one directory and run:

    sha256sum -c --ignore-missing SHA256SUMS.txt

Every file you downloaded must print `OK`. If one prints `FAILED`, delete it and download it again.
The checksums protect against a damaged download. They come from the same release page, so they
do not protect against a compromised release.

### RPM (RHEL, Rocky, Alma, Fedora family)

`spacenavd` and `libspnav` are not in the base repositories of RHEL 9 and its clones. Enable
EPEL first:

    sudo dnf install -y epel-release
    sudo dnf install ./dofscroll-1.0.0-1.x86_64.rpm

The package declares the dependency `spacenavd` (CPack setting `CPACK_RPM_PACKAGE_REQUIRES`).
The shared libraries (`libspnav`, X11) are added by rpmbuild's automatic
dependency detection (unverified). `dnf` installs what is missing.

### DEB (Debian, Ubuntu family)

    sudo apt install ./dofscroll_1.0.0_amd64.deb

The package declares the dependency `spacenavd` (`CPACK_DEBIAN_PACKAGE_DEPENDS`). Library
dependencies are generated by `dpkg-shlibdeps` (`CPACK_DEBIAN_PACKAGE_SHLIBDEPS`). Whether `spacenavd` exists in your release's
repositories: unverified.

### Which distributions are tested

An install smoke test (`.github/workflows/linux-smoke.yml`, script `scripts/smoke-install.sh`)
installs the built RPM and DEB with the distribution package manager in a fresh container and
runs `dofscroll --version`, `dofscroll --help` and, if the package contains it, `dofscroll-ui
--version` headless. It checks that the package installs and starts, nothing more: not
scrolling, not a desktop session, not a SpaceMouse. The table lists what the smoke test covers;
any other distribution is untested.

| Distribution | Package | Smoke test |
|---|---|---|
| Rocky Linux 9 (with EPEL) | RPM | covered, build distribution; installs and starts (2026-10-19) |
| Debian 12 | DEB | covered, build distribution; installs and starts (2026-10-19) |
| Rocky Linux 10 | RPM | not tested in CI; the test on 2026-10-19 showed that it **does not install**: `spacenavd` is not available in its repositories |
| Fedora 42 | RPM | covered, informational; installs and starts (2026-10-19) |
| Debian 13 | DEB | covered, informational; installs and starts (2026-10-19) |
| Ubuntu 24.04 | DEB | covered, informational; installs and starts (2026-10-19) |
| everything else (Alma, openSUSE, Arch, older releases, ...) | | untested |

"Installs and starts" means the smoke test installed the package in a fresh container and ran `dofscroll --version`; it says nothing about a real desktop or device. "Informational" entries report their result in the job summary of the `linux-smoke` run but never
block a release; a failure there (for example a missing `spacenavd` in that release's
repositories) means the package does not install there without extra steps. Check the latest run
of `linux-packages-dry-run` for the current result before relying on one of them.

### TGZ

The archive has the top directory `dofscroll-1.0.0-Linux/` and contains a tree rooted at `usr/`.
Extract it and copy it into `/usr` (or another prefix):

    tar xzf dofscroll-1.0.0-Linux.tar.gz
    sudo cp -a dofscroll-1.0.0-Linux/usr/. /usr/

You must install the dependencies yourself (see [section 4](#4-build-from-source) for the
package names; the run-time packages are the non-`-devel` ones).

### What a package installs

Checked on the TGZ built on a RHEL 9 machine:

| Path | Content |
|---|---|
| `/usr/bin/dofscroll` | The daemon. |
| `/usr/bin/dofscroll-ui`, `/usr/bin/dofscroll_de.qm`, `/usr/share/applications/dofscroll.desktop`, `/usr/share/icons/hicolor/scalable/apps/dofscroll.svg`, `dofscroll-ui.service` | The Qt interface with its German catalog, menu entry, icon and user unit. Only in packages built where Qt6 was available (see "Qt interface" below). |
| `/usr/lib/systemd/user/dofscroll.service` | User units, rendered at install time so `ExecStart` points at the real program path (`/usr/bin/...` for a package). The directory is always `<prefix>/lib/systemd/user`, never `lib64`. |
| `/usr/share/dofscroll/udev/70-dofscroll-uinput.rules` | uinput udev rule, shipped as an example only. It is not active until you copy it (step 5). |
| `/usr/share/dofscroll/examples/` | Example configs, `default/`, `modes/` and `buttons/` (button modes, see [button-modes.md](button-modes.md)). |
| `/usr/share/locale/de/LC_MESSAGES/dofscroll.mo` | German translation. |
| `/usr/share/doc/dofscroll/` | `LICENSE` and a copy of the readme. |

The unit and rule locations are covered by the `install_layout` test (an install into a temporary
directory). The RPM and DEB files themselves are built by the release workflow and have not
been checked on a real machine yet (unverified until the first release).

## 2. First-time setup

dofscroll complements the vendor driver instead of duplicating it: a button mapping that is the same everywhere and always (for example a button that sends Esc) is configured in the driver (spacenavd's spnavrc on Linux, the 3Dconnexion driver on Windows and macOS); dofscroll's own button actions are for bindings that depend on dofscroll's state: they apply only in a joystick mode or profile, switch or toggle joystick modes and behavior, or work together with the axis handling; dofscroll also handles what the driver does not: shaping scroll and zoom from the six axes, keys derived from axes, and per-program and per-device profiles. Setup step: configure plain button mappings in the driver (see [modes.md](modes.md#buttons-and-the-vendor-driver)) before you tune dofscroll.

Do these steps once per machine. Steps 1 and 5 need root.

1. Enable the SpaceMouse driver:

        sudo systemctl enable --now spacenavd

2. Check that the driver sees the device:

        systemctl status spacenavd

3. Check that systemd finds the user units (the package installs them where systemd looks):

        systemctl --user daemon-reload
        systemctl --user list-unit-files 'dofscroll*'

4. Start the services. They then start with every graphical session. 

        systemctl --user enable --now dofscroll.service dofscroll-ui.service

   Later you can switch the autostart on or off with the "Start at login" checkbox in the
   settings window of the interface. It runs
   `systemctl --user enable` or `disable` (without `--now`) for both units, so it affects the next
   login only. The checkbox is greyed out, with a tooltip, if the units are masked, static,
   enabled only until reboot, or unknown to systemd (for example when it runs from a build folder
   instead of an installed package).

   The Qt UI (`dofscroll-ui`) uses the same switch through `src/platform/autostart_platform.hpp`
   (`queryAutostart`, `setAutostart`) on all three systems; it handles the daemon and the UI
   together: "enabled" only if both start at login, a mix is shown as partial and ticking the box
   repairs it. If the UI is not installed, only the daemon is switched. On Linux the UI has its
   own unit `dofscroll-ui.service` (installed when the UI is built).

   **Qt interface.** `dofscroll-ui` is the only tray icon and settings window on Linux, Windows and
   macOS; it is also started from the application menu ("dofScroll"). The old GTK tray
   (`dofscroll-tray`, `dofscroll-tray.service`) was removed in 0.1.1 (#43); see "Upgrade"
   below for what happens to an existing installation. Without the Qt interface (a package built
   where Qt6 was not available) there is no tray and no settings window: edit the configuration
   file by hand.

   Runtime needs of the Qt interface (single package, no subpackage): the RPM requires
   `qt6-qtbase-gui` and `qt6-qtsvg` (Rocky/RHEL 9: AppStream), the DEB depends on the `libqt6*`
   packages that `dpkg-shlibdeps` finds (Debian 12: `libqt6widgets6`, `libqt6gui6`,
   `libqt6svg6`). The release packages are built in `rockylinux:9` and `debian:12` containers; if
   Qt6 cannot be installed there, that package contains only the daemon and the build log says so. The package
   build is not verified on a real desktop.

5. Optional, only for Wayland or if you set `BACKEND = uinput`: activate the udev rule for
   `/dev/uinput`.
   The package deliberately does not activate the rule (it makes `/dev/uinput` accessible to the
   logged-in seat user), it only ships it as an example. Copy it and reload udev:

        sudo cp /usr/share/dofscroll/udev/70-dofscroll-uinput.rules /etc/udev/rules.d/
        sudo udevadm control --reload && sudo udevadm trigger

   Log out and in once. Details and the reason why you must not join the `input` group:
   [packaging/README-uinput.md](../packaging/README-uinput.md). If `/dev/uinput` does not exist,
   run `sudo modprobe uinput`.

### First start: seeding

When the Qt interface starts and no config exists, it creates
`~/.config/dofscroll/dofscroll.conf` from `examples/default/dofscroll.conf`. It never overwrites an
existing file. The joystick modes and button modes are built into the program and are not copied.
The daemon cannot write to that directory, so only the interface seeds. Without it, copy the file yourself:

    mkdir -p -m 0700 ~/.config/dofscroll
    cp /usr/share/dofscroll/examples/default/dofscroll.conf ~/.config/dofscroll/

The interface looks for the default configuration in `$DOFSCROLL_EXAMPLES`, next to the executable, in
`../share/dofscroll/examples`, then `/usr/local/share/dofscroll/examples` and
`/usr/share/dofscroll/examples`.

### Check that it works

    systemctl --user status dofscroll.service
    journalctl --user -u dofscroll.service -f

The log shows the device name and button count when the SpaceMouse is connected. Hardware
behavior (scrolling, zoom, buttons) can only be confirmed by you on your device. See
[troubleshooting.md](troubleshooting.md) if it does not work.

## 3. Upgrade, uninstall, migration

### Upgrade

Install the newer package over the old one:

    sudo dnf upgrade ./dofscroll-<new>.rpm       # or: sudo dnf install ./dofscroll-<new>.rpm
    sudo apt install ./dofscroll_<new>_amd64.deb # Debian family

The package then does a best-effort restart on its own: for every logged-in user it runs
`systemctl --user daemon-reload` and `try-restart` of `dofscroll.service` and
`dofscroll-ui.service` (only units that are running are restarted; a fresh install does
nothing; the step never fails the upgrade and never touches your config). If nobody was logged in
through logind, or you run the program from a terminal, restart by hand:

    systemctl --user daemon-reload
    systemctl --user restart dofscroll.service dofscroll-ui.service

You can also use the tray menu: **Restart daemon** (releases held keys first) and **Restart
interface**. `dofscroll-ui.service` has `Wants=dofscroll.service`, so starting only the interface
also starts the daemon.

**Upgrading from a version with the GTK tray (before 0.1.1).** The GTK tray
(`dofscroll-tray`, `dofscroll-tray.service`) no longer exists; `dofscroll-ui` replaces it. If you
had `dofscroll-tray.service` enabled, the package upgrade step migrates the autostart once, for
every logged-in user, best effort: it stops and disables `dofscroll-tray.service`, enables
`dofscroll-ui.service` and starts it if the tray was running (a system-wide `--global` enable is
moved the same way). It only changes systemd unit links, never your configuration, and it is
skipped when the new package has no Qt interface. If you were not logged in during the upgrade,
or the link is still there, do it by hand:

    systemctl --user disable --now dofscroll-tray.service
    systemctl --user enable --now dofscroll-ui.service
    rm -f ~/.config/systemd/user/dofscroll-tray.service   # only if you copied the unit there yourself

Your config in `~/.config/dofscroll/` is never touched by a package. If you copied the units
in step 3, repeat the copy and the `sed` command when the unit files changed in the release
notes.

### Uninstall

    systemctl --user disable --now dofscroll.service dofscroll-ui.service
    rm -f ~/.config/systemd/user/dofscroll.service ~/.config/systemd/user/dofscroll-ui.service
    sudo dnf remove dofscroll        # or: sudo apt remove dofscroll
    sudo rm -f /etc/udev/rules.d/70-dofscroll-uinput.rules   # if you installed it

Your config stays. Remove it with `rm -r ~/.config/dofscroll` if you want. For a TGZ install,
delete the files listed in "What a package installs".

### Migration from the old `spnav-scroll` names

The project used to be called `spnav-scroll`. Old config paths
`~/.config/spnav-scroll/spnav-scroll.conf` and `~/.config/spnav-scroll.conf` are still read as a
fallback. The interface copies the old file to `~/.config/dofscroll/dofscroll.conf` when it starts (a
symlink is recreated as a symlink). The old file is not deleted. After you checked the settings:

    rm -r ~/.config/spnav-scroll ~/.config/spnav-scroll.conf

Old units and binaries are not removed automatically. Remove them:

    systemctl --user disable --now spnav-scroll.service spnav-scroll-tray.service
    rm -f ~/.config/systemd/user/spnav-scroll*.service
    sudo rm -f /usr/local/bin/spnav-scroll /usr/local/bin/spnav-scroll-tray

Restart the interface unit once after the first start of a new version
(`systemctl --user daemon-reload && systemctl --user restart dofscroll-ui.service`) so the
current sandbox settings apply.

## 4. Build from source

### Dependencies

Run the check first. It lists missing packages and prints the install command for your distribution:

    cmake -S . -B build
    cmake --build build --target check-deps

| Distribution | Packages |
|---|---|
| RHEL 9 family | `sudo dnf install -y epel-release` then `sudo dnf install -y gcc-c++ cmake pkgconf-pkg-config spacenavd libspnav-devel libX11-devel libXtst-devel gettext` |
| Debian family | `sudo apt install g++ cmake pkg-config libspnav-dev libx11-dev libxtst-dev gettext` (taken from the CI job and the check-deps target; the Debian line is unverified here) |

CMake 3.16 or newer is required. If your system has an older one: `pip install --user cmake`.
`gettext` is only needed for the German translation.

### Configure, build, test, install

    cmake -S . -B build
    cmake --build build -j4
    ctest --test-dir build --output-on-failure
    sudo cmake --install build                    # default prefix /usr/local
    sudo cmake --install build --prefix /usr      # or choose a prefix
    DESTDIR=/tmp/stage cmake --install build      # stage for inspection

Options at configure time:

| Option | Default | Effect |
|---|---|---|
| `-DDOFSCROLL_HARDEN=OFF` | ON | Switch off the hardening flags. |
| `-DDOFSCROLL_SANITIZE=ON` | OFF | ASan/UBSan build. |
| `-DDOFSCROLL_WERROR=ON` | OFF | Treat warnings as errors. |

The install rules put the units in `<prefix>/lib/systemd/user` and the udev rule example in
`<prefix>/share/dofscroll/udev` (nothing goes into an active udev directory; `install-udev` activates it), with `ExecStart` pointing at `<prefix>/bin`. With the default prefix
`/usr/local`, systemd does not read `/usr/local/lib/systemd/user` by default; for a local install
link the units as described in "Run from the build tree" below, or install with
`-DCMAKE_INSTALL_PREFIX=/usr`.

Packages: `cd build && cpack -G TGZ` (also `RPM` with `rpmbuild`, `DEB` with `dpkg-deb`).

### Run from the build tree

For development, link the build results instead of installing copies. The target only prints
the commands and runs nothing with sudo:

    cmake --build build --target install-user-links

Run the printed commands. The binaries then come from `build/`, the units from `build/systemd-dev/`
(rendered for `/usr/local/bin`), so a rebuild takes effect after a restart. Stop the services before rebuilding
(`Text file busy`): `systemctl --user stop dofscroll.service dofscroll-ui.service`. Do not move
the checkout afterwards, or the links break.

Other targets: `check-fast` (-Werror build and tests), `check` (adds sanitizers, cppcheck,
hardening check), `check-config` (validates the example configs), `lint`, `install-udev`,
`uninstall` (uses `install_manifest.txt`).

### Qt interface

The Qt6 interface (`dofscroll-ui`, see [ui.md](ui.md)) is built when Qt6 Widgets is found (CMake
option `DOFSCROLL_UI`). Linux: install the distribution's Qt6 development packages
(Debian family: `qt6-base-dev qt6-tools-dev-tools libqt6svg6-dev`). Windows and macOS builds
bundle the Qt libraries. Decisions: `docs/ui-options.md`. `dofscroll-ui --self-test` checks that
the window can be created.

## 5. Windows and macOS

The Windows and macOS ports are experimental: they have **not been tested with a real SpaceMouse**
by the maintainer (CI builds only), and the packages are **unsigned**. The plan and the state of each work package
are in [work-plan.md](work-plan.md); how the packages are built is in
[release-process.md](release-process.md).

### Windows installer and ZIP

1. Download `dofscroll-<version>-windows-x64-setup.exe` (or the `-portable.zip`) and verify it as
   in section 1.
2. Run the installer. Because it is not code-signed, Windows SmartScreen shows "Windows protected
   your PC": click **More info**, then **Run anyway**. No administrator rights are needed; the
   default folder is `%LOCALAPPDATA%\Programs\dofscroll`.
3. The components page has **Start the daemon at logon** (off by default; Run key value `dofscroll`
   of the current user). The Start menu folder `dofscroll` opens the settings window
   (`dofscroll-ui.exe`); `dofscroll.exe` is the daemon (no window).
4. Config is read from `%APPDATA%\dofscroll\dofscroll.conf`, logs are in
   `%LOCALAPPDATA%\dofscroll\dofscroll.log`.
5. The official 3Dconnexion driver can stay installed and running: dofscroll is designed to work next
   to it. Whether both can read the SpaceMouse at the same time is **not verified on real hardware yet**;
   please run the 5 minute test and attach its file to issue #36:
   `powershell -ExecutionPolicy Bypass -File scripts\test-driver-coexistence.ps1` (from the install folder).
   The diagnostic tool `dofscroll-hidprobe.exe` sits next to `dofscroll.exe` (run it from a terminal:
   `dofscroll-hidprobe --list`). See [troubleshooting.md](troubleshooting.md#the-official-3dconnexion-driver-and-dofscroll).
6. The UI's "Start at login" switch writes the values `dofscroll` and `dofscroll-ui` under
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; the installer's autostart component writes
   `dofscroll`, and the uninstaller removes both.

**Upgrade:** run the new installer over the old one (same folder). It stops the daemon (releasing held
keys) and a running `dofscroll-ui.exe` of that install before replacing the files. If the daemon was
running, the installer starts it again afterwards, also for a silent `/S` install, then the
interface if that was running too (interactive installs only). The finish-page box "Start the
dofscroll daemon now" does not start a second daemon. A fresh install, or an update with the daemon
stopped before, starts nothing on its own. The tray items **Restart daemon** and **Restart
interface** restart the programs without the installer.

**Uninstall:** Settings > Apps > dofscroll, or the Start menu entry "Uninstall dofscroll". It stops
the daemon and removes the program folder, the Start menu entries and the autostart value; your
configuration in `%APPDATA%\dofscroll` stays. Silent install: `setup.exe /S /AUTOSTART=1`.
The ZIP needs no installation: unpack it, start `dofscroll.exe`, and use
`scripts\install-autostart.ps1` if you want autostart. Installer and ZIP both contain
`dofscroll-hidprobe.exe` and `scripts\test-driver-coexistence.ps1`.

`dofscroll-ui.exe` has no console of its own; started from cmd or PowerShell it writes `--help`,
`--version` and `--self-test` output into that console (not when started by double click). The
German catalog `dofscroll_de.qm` is installed next to it. Only a real Windows machine can verify
this; [port-windows-checklist.md](port-windows-checklist.md) lists what a tester has to verify.

### macOS image

1. Download `dofscroll-<version>-macos-arm64.dmg` (Apple silicon), verify it, open it and drag
   `dofscroll.app` to Applications. `README-first-run.txt` in the image repeats the steps below.
2. The app is not signed with a Developer ID and not notarized (ad-hoc signature only), so
   Gatekeeper blocks the first start. Right-click the app > **Open** > **Open**; on macOS 15 and
   later use System Settings > Privacy & Security > **Open Anyway**. Alternatively:
   `xattr -dr com.apple.quarantine /Applications/dofscroll.app`.
3. In System Settings > Privacy & Security grant **Input Monitoring** and **Accessibility** to
   `/Applications/dofscroll.app/Contents/Resources/daemon/dofscroll`, then restart the daemon.
4. Autostart (per-user LaunchAgent, no sudo):
   `sh /Applications/dofscroll.app/Contents/Resources/launchagent/install-launchagent.sh --daemon /Applications/dofscroll.app/Contents/Resources/daemon/dofscroll`
5. **Upgrade** (no installer script, nothing is stopped for you): choose **Quit** in the tray menu to
   close the interface, stop the daemon (`launchctl bootout gui/$(id -u)/io.github.dofscroll.daemon`
   if autostart is installed, otherwise quit the process), drag the new `dofscroll.app` over the old
   one in Applications, grant the permissions again if macOS asks, then start the app (and the
   daemon: log in again or `launchctl bootstrap` / run `install-launchagent.sh`; if the LaunchAgent
   is still loaded, `launchctl kickstart -k gui/$(id -u)/io.github.dofscroll.daemon` starts the new
   binary). Your configuration stays. The tray items **Restart daemon** (`launchctl kickstart -k`) and **Restart
   interface** are for restarts without an upgrade; the app does not detect a newer app on disk.
6. The menu bar icon is a template icon. macOS does not deliver a click on a tray icon that has a
   menu, so open the window with **Settings...** in the menu. The German catalog is inside the app
   (`Contents/MacOS/dofscroll_de.qm`). Neither is verified on real hardware.
7. **Uninstall:** run `.../launchagent/uninstall-launchagent.sh`, then move the app to the Trash.
   Configuration in `~/Library/Application Support/dofscroll` stays.
8. **Together with the official 3Dconnexion driver:** keep the driver installed and running; dofscroll is
   designed to work next to it, but this is **not verified on a real Mac yet**. Please run the 5 minute
   test (it changes nothing) and attach its file to issue #37:
   `sh /Applications/dofscroll.app/Contents/Resources/diagnostics/test-driver-coexistence.sh`.
   The diagnostic tool is `/Applications/dofscroll.app/Contents/Resources/daemon/dofscroll-hidprobe`
   (run it from Terminal, which needs the Input Monitoring permission: `... dofscroll-hidprobe --list`).
   See [troubleshooting.md](troubleshooting.md#the-official-3dconnexion-driver-and-dofscroll).

See [port-macos.md](port-macos.md) and [packaging/macos/README.md](../packaging/macos/README.md).
Building from source on either system: `cmake -S . -B build && cmake --build build`.
